# SD card audit (Pi 3A+, read-only)

Audited 2026-10-03 from a Windows PC where the card mounted as `L:\`. Nothing
was written to the card: no fsck/chkdsk, no Imager, no diskpart, no
`wsl --mount`. Only the FAT boot partition was readable, so everything about the
root filesystem below is inference, not observation. Confidence is stated where
it matters.

**Secrets:** no secret values are reproduced here. Only paths and risk are given.

## 1. What was inspected and what wasn't

| Item | Status |
|---|---|
| Partition 1, FAT32 boot (`L:\`) | Read: full directory listing, `config.txt`, `cmdline.txt`, `issue.txt`, `meta-data`, `user-data` and `network-config` (values masked before viewing), plus the on-card `overlays/README` (to verify overlay parameters against the installed firmware) |
| Partition 2, ext4 root | **Not readable.** Windows doesn't mount ext4, and the session's shell could not mount the drive. Its existence is inferred from `root=PARTUUID=…-02` in `cmdline.txt`. |
| Any further partition | Unknown. The kernel command line names only partition 2. |
| Card size, free space, wear | Not available through the FAT view. |

Not checked because the root is unreadable: `/etc/os-release`, installed
packages (cog/WPE, GStreamer, mpv, node, python, HAP-python), enabled systemd
units, `/opt` (v2 install), `/etc/fstab`, zram/swap, journald config and size,
disk usage, `/var/lib/cloud`, NetworkManager connection files.

Side note: a `System Volume Information` folder exists on `L:\`. Windows creates
it on FAT volumes; it's harmless.

## 3. Findings

### Boot partition
- **[KEEP]** `arm_64bit=1`, `kernel8.img`, Lite image. Matches the v3 target.
- **[KEEP]** `dtoverlay=vc4-kms-v3d,cma-128`. Required for mpv on DRM; the
  on-card README confirms `cma-128` is a valid parameter.
- **[KEEP]** `dtoverlay=vc4-kms-dsi-waveshare-panel-v2,5_0_inch_a`. The installed
  overlay README describes `5_0_inch_a` as 5.0" 720x1280 2-lane, and the overlay
  requires `vc4-kms-v3d`. **Verify in M1:** `HARDWARE.md` lists the panel as
  "5-DSI-TOUCH-**B**", but the overlay parameter is `_a`. Confirm the exact panel
  model and the matching parameter.
- **[KEEP]** `dtoverlay=hifiberry-dac` for the MAX98357A, and
  `dtparam=i2c_arm=on` for the BH1750.
- **[KEEP]** `disable_fw_kms_setup=1`, `max_framebuffers=2`, `auto_initramfs=1`
  (the overlayfs root depends on the initramfs), `cfg80211.ieee80211_regdom=US`,
  `rootwait`, `fsck.repair=yes`.
- **[CHANGE]** `dtparam=audio=on` → `off`. The unused onboard sound card would
  sit next to the I²S one and confuse ALSA device numbering for `SleepboxVol`.
- **[CHANGE]** `camera_auto_detect=1` → `0` and `display_auto_detect=1` → `0`.
  No camera, and the DSI panel is declared explicitly; auto-detection only adds
  probe time.
- **[CHANGE]** `vc4-kms-v3d,cma-128` → add `nohdmi` (listed in the overlay
  README as "Disable HDMI output"). This is the KMS way to turn HDMI off. Check
  in M1 that the DSI panel still comes up.
- **[CHANGE]** Add `dtoverlay=disable-bt`, `temp_soft_limit=70`, `boot_delay=0`,
  `disable_splash=1`. All in the v3 spec. `disable-bt` also returns the PL011
  UART to GPIO 14/15 for a debug console. The official docs say
  `temp_soft_limit` applies to the 3B+; the 3A+ uses the same BCM2837B0, and v2
  throttled at 60 °C on this board, so it very likely applies too. Confirm in M1
  (`vcgencmd get_config temp_soft_limit`).
- **[CHANGE]** Move `dtparam=i2c_arm=on` (and `audio=off`) above the overlay
  lines. `dtparam` lines after a `dtoverlay` are scoped to that overlay first;
  base-tree parameters are clearest set before any overlay loads.
- **[REMOVE]** `arm_boost=1`. Pi 4/400 only; no effect on a 3A+.
- **[REMOVE]** `video=DSI-1:720x1280e,rotate=90` from `cmdline.txt`. It
  contradicts the design rule "no kernel rotation; device encodes are
  pre-rotated". `rotate=` probably affects only the fbcon console, not mpv's DRM
  output (medium confidence), so it is unneeded and misleading. If mpv can't find
  the right mode after removal, try `video=DSI-1:720x1280@60` *without*
  `rotate`.
- **[REMOVE]** `console=tty1`. No boot text on the night-light panel. Keep
  `console=serial0,115200` for debugging until M5.
- **[CHANGE]** Add `quiet loglevel=3 logo.nologo vt.global_cursor_default=0`.
- **[REMOVE]** `ds=nocloud;i=rpi-imager-…` and the three cloud-init files, but
  only *after* first-boot provisioning has run. Cloud-init runs several services
  on every boot and its input files hold secrets.
- **[KEEP]** `bootcode.bin`, `start*.elf`, `fixup*.dat`, `initramfs_2712`,
  `kernel_2712.img`, the other dtbs, `LICENCE.broadcom`. Pi 4/5 files are dead
  weight on a 3A+ but harmless.

### Secrets and security
- **[RISK]** `L:\network-config` holds the Wi-Fi PSK on a FAT partition any PC
  or phone with a card reader can read.
- **[RISK]** `L:\user-data` holds a password hash for `sleepbox`, with
  `ssh_pwauth: true`. A weak password is crackable offline, and password SSH is
  more exposure than a key-only login needs. No SSH keys on the card.
- **[RISK]** The same secrets are almost certainly copied into the root
  filesystem on first boot (`/var/lib/cloud/…`, and the PSK in
  `/etc/NetworkManager/system-connections/`). Not verified.
- **[RISK]** Tool-handling note: during the audit the Wi-Fi network *name*
  appeared once in console output (the masking pattern didn't cover it). It is
  not a password and is not in this file or in git.

### Root filesystem and RAM (inferred only)
- **[RISK]** v2 leftovers can't be ruled out: cog/WPE kiosk, HAP-python, an
  `/opt` install, a persistent journald, apt timers. Unverified.
- **[RISK]** RAM headroom is likely well below the "~200 MB" in
  `ARCHITECTURE.md`. That figure is roughly 512 − 270 − slack and doesn't account
  for:
  - **`gpu_mem`**: on a Pi 3, `v4l2m2m` hardware decode runs through the
    VideoCore firmware, so `gpu_mem` still matters under KMS. The default on a
    512 MB board is 64 MB (I believe). That memory is removed from Linux
    entirely.
  - **CMA (128 MB)**: reserved for vc4/codec buffers, but free CMA pages *are*
    usable by Linux for page cache and movable allocations and are counted in
    `MemAvailable`. So it costs less than a full 128 MB unless the GPU pipeline
    actually fills it.
  - The kernel, systemd, avahi, NetworkManager and page cache.

  Realistic headroom before zram is probably 50–150 MB, which may be tight
  against the M1 gate (`free -m` ≥ 150 MB available). In M1, record
  `vcgencmd get_mem gpu`, `MemTotal` and `CmaFree` from `/proc/meminfo`. Do not
  change `gpu_mem` or CMA until hardware decode is confirmed working; if the gate
  then fails, try `cma-96` first. `ARCHITECTURE.md` was not edited (CLAUDE.md
  rule 10).

## 5. Recommendation: re-flash

**Re-flash** with current Raspberry Pi OS Lite 64-bit rather than cleaning this
card:

1. The root is unverified and may carry the whole v2 stack. Cleaning an unknown
   root by hand costs more than 10 minutes of Imager.
2. The Wi-Fi credential and the user password hash should be rotated anyway, and
   they are spread over both partitions.
3. The card is only half-configured for v3 (§4), and M1 expects a known-clean
   base plus `deploy/install.sh`.
4. SD wear is unknown. Use the Samsung Endurance card from the parts list.

The boot-side delta is small: the image type is right and the overlay lines are
correct.

**OS version: Trixie, not Bookworm** (medium confidence). No repo doc pins
Bookworm, Trixie is Imager's default and what the card already runs, and
Debian 12's regular security support ended in June 2026 (it is now in LTS).
Verify in M1 that `mpv --hwdec=v4l2m2m-copy` decodes cleanly on Trixie and
measure boot time with cloud-init disabled. If either fails, fall back to the
Bookworm "legacy" image; only provisioning changes.

In Imager: set a **new** Wi-Fi password if there's any doubt who has seen the old
one (rotate it on the router), keep username/hostname `sleepbox`, paste an SSH
**public key**, turn password SSH off, and never save the Wi-Fi password anywhere
that syncs to git.

## 6. Proposed v3 boot files

### config.txt
This card only ever runs on a 3A+, so replace the whole file (back up the stock
one first). Keeping the stock top-of-file lines would load `vc4-kms-v3d` twice
and contradict `audio=off` and the auto-detect settings, and the
`[cm4]`/`[cm5]`/`[pi5]` sections do nothing on a 3A+.

**config.txt does not support inline comments.** Anything after the `=` is part
of the value, so every comment must be on its own line starting with `#`.

```
# Tuesday Dream Machine v3 - Raspberry Pi 3A+ only
[all]

# Base-tree parameters first, before any overlay loads.
# I2C-1 on GPIO2/3 for the BH1750 (0x23)
dtparam=i2c_arm=on
# No onboard sound card; the I2S DAC is the only ALSA card
dtparam=audio=off

# --- display / GPU ---
# KMS/DRM for mpv; 128 MB CMA per spec; HDMI output off
dtoverlay=vc4-kms-v3d,cma-128,nohdmi
# Required by vc4-kms-v3d
max_framebuffers=2
# Kernel owns modesetting; firmware must not inject video=
disable_fw_kms_setup=1
# Waveshare 5" 720x1280 DSI + GT911 touch (verify A/B model in M1)
dtoverlay=vc4-kms-dsi-waveshare-panel-v2,5_0_inch_a
# No camera, and the panel is declared above: skip probing
camera_auto_detect=0
display_auto_detect=0
# gpu_mem left at the default: the Pi 3 v4l2m2m decoder runs on the firmware

# --- audio ---
# I2S (GPIO18/19/21) for the MAX98357A
dtoverlay=hifiberry-dac

# --- radios ---
# Bluetooth off; frees the PL011 UART on GPIO14/15 for a serial console
dtoverlay=disable-bt

# --- boot speed / thermals ---
# Firmware default is 1 s
boot_delay=0
disable_splash=1
# Raise the soft throttle point from 60 C (heatsink + vented box)
temp_soft_limit=70
# Needed for the overlayroot initramfs (M5)
auto_initramfs=1
arm_64bit=1
```

`disable_overscan` is dropped: it has no effect under KMS.

### cmdline.txt
Apply this **after** first boot. Imager adds its own `ds=nocloud;…` token, and
removing it before first boot stops Wi-Fi, user and SSH provisioning. Keep the
PARTUUID Imager writes; don't copy the old one. One line:

```
console=serial0,115200 root=PARTUUID=<set by Imager>-02 rootfstype=ext4 rootwait fsck.repair=yes quiet loglevel=3 logo.nologo vt.global_cursor_default=0 cfg80211.ieee80211_regdom=US
```

| Token | Why |
|---|---|
| `console=serial0,115200` | Debug serial console on GPIO14/15 (free after `disable-bt`). Optional to remove at M5. |
| *(no `console=tty1`)* | No boot text on the panel. |
| `root=PARTUUID=…-02 rootfstype=ext4 rootwait` | Standard Pi root; `rootwait` for slow SD init. |
| `fsck.repair=yes` | A headless device must never stop at an emergency prompt after a power cut. With a read-only overlay root the root fsck is near-instant; the real protection is on the writable data partition (`nofail`, fsck pass 2). |
| `quiet loglevel=3` | Kernel prints errors only; shorter boot. |
| `logo.nologo` | No Tux on the panel. |
| `vt.global_cursor_default=0` | No blinking cursor before mpv takes the display. |
| `cfg80211.ieee80211_regdom=US` | Wi-Fi regulatory domain. |
| *(no `video=…`)* | No kernel rotation or forced mode; encodes are pre-rotated. |
| *(no `ds=nocloud;…`)* | Cloud-init is finished and disabled; see §7. |

When M5 enables the read-only root, `raspi-config nonint enable_overlayfs` adds
its own token to this line (believed to be `overlayroot=tmpfs`; verify) and
needs the initramfs, so keep `auto_initramfs=1`.

### Differences from docs/HARDWARE.md
The `HARDWARE.md` fragment is close but incomplete. It is **not** changed in
this commit (CLAUDE.md rule 10); proposed follow-ups for Peter to approve:
- Add `audio=off`, `nohdmi`, `boot_delay=0`, `disable_splash=1`,
  `camera_auto_detect=0`, `display_auto_detect=0`.
- It says the GT911 touch shares the BH1750's I²C bus. With the `-panel-v2`
  overlay the touch controller is on the DSI connector's own I²C bus. Check in
  M1 (`i2cdetect -y 1` should show only 0x23).
- Reconcile the panel name (5-DSI-TOUCH-B) with the overlay parameter
  (`5_0_inch_a`).
- Add an explicit "no `video=…,rotate=` in `cmdline.txt`" note.

## 7. Boot-time / RAM / SD-wear checklist (on the fresh image)

### Boot time (target ≤ 30 s)
- [ ] After provisioning: `sudo touch /etc/cloud/cloud-init.disabled`, then
      delete `user-data`, `network-config` and `meta-data` from the boot
      partition (secrets) and drop `ds=nocloud;…` from `cmdline.txt`.
- [ ] `sudo systemctl disable NetworkManager-wait-online.service` (nothing needs
      the network before sleepd; Matter and the phone UI reconnect on their own).
- [ ] Disable if present: `bluetooth.service`, `hciuart.service`,
      `ModemManager.service`, `triggerhappy.service`, `e2scrub_all.timer`,
      `rpi-eeprom-update.service` (no EEPROM on a 3A+), `userconfig.service`,
      `keyboard-setup.service`, `console-setup.service`. Don't install `cups`.
- [ ] **Keep:** `avahi-daemon` (Matter and `sleepbox.local` need mDNS),
      `systemd-timesyncd` (no RTC; the bedtime schedule needs a correct clock),
      `NetworkManager`, `ssh` (key-only), and `fstrim.timer` (weekly, no
      boot-time cost, helps SD wear-levelling on the writable partition).
- [ ] Verify with `systemd-analyze` and `systemd-analyze critical-chain`. Goal:
      cold boot to a playing scene ≤ 30 s (M1 acceptance).
- [ ] Keep IPv6 enabled (Matter requires it). Turn Wi-Fi power save off for
      reliable mDNS: `wifi.powersave = 2` in a NetworkManager conf drop-in.

### RAM (512 MB, CMA 128)
- [ ] Record `vcgencmd get_mem gpu`, `MemTotal` and `CmaFree` on first boot.
- [ ] 256 MB zram swap, lz4 (cheaper than zstd on a Cortex-A53), via
      zram-generator or zram-tools. First check `swapon --show`: Trixie images
      may already enable zram (rpi-swap) or a swap file. Run exactly one swap;
      disable `dphys-swapfile` if present.
- [ ] Re-check `free -m` after a 30 min soak. Gate: ≥ 150 MB available.
- [ ] Per-process budgets from CLAUDE.md: mpv video ≤ 90, mpv audio ≤ 30,
      sleepd ≤ 50, matter-bridge ≤ 100 MB RSS. Add `MemoryMax=` to the units as
      a backstop.
- [ ] If the gate fails, try `cma-96` and re-test hardware decode before cutting
      anything else. Leave `gpu_mem` alone unless decode is proven to work at a
      lower value.
- [ ] Don't install a desktop, cog/WPE, GStreamer plugins, HAP-python, or Node
      outside `matter-bridge/`.

### Reliability (M5)
- [ ] Hardware watchdog: `RuntimeWatchdogSec=15` (or similar) in
      `/etc/systemd/system.conf.d/watchdog.conf`, so systemd feeds the bcm2835
      watchdog and a hung kernel reboots.
- [ ] `Restart=always` on every sleepbox unit.

### SD wear and power-cut safety
- [ ] Volatile journal: `/etc/systemd/journald.conf.d/volatile.conf` with
      `Storage=volatile` and `RuntimeMaxUse=16M`.
- [ ] Disable and mask `apt-daily.timer`, `apt-daily-upgrade.timer`,
      `man-db.timer`. Update by re-imaging or a deliberate maintenance boot.
- [ ] Read-only root via overlayfs (`raspi-config nonint enable_overlayfs`, M5),
      with `/opt/sleepbox/config` on a small separate writable ext4 partition
      mounted `noatime,nofail`, fsck pass 2. Plan partition 3 before the
      first-boot root expansion.
- [ ] `noatime` everywhere; no persistent `/var/log`; tmpfs for `/tmp`.
- [ ] Debounced state saves (5 s) are the only regular writes. Use the Endurance
      card and keep a spare, flashed.
- [ ] M5 acceptance: 10 hard power pulls with clean boots and resume.

## 8. Security note

Secrets found (paths only; values are not recorded anywhere in the repo):
- `L:\network-config` (boot partition): Wi-Fi credential.
- `L:\user-data` (boot partition): password hash for user `sleepbox`.
- Likely copies on the unreadable root: `/var/lib/cloud/…` and
  `/etc/NetworkManager/system-connections/…`. Not verified.

What to do:
1. Re-flash (§5), which destroys all on-card copies. Deleting only the two FAT
   files leaves the root copies.
2. If the card has been out of your hands, or the Wi-Fi password is reused
   elsewhere, **change the Wi-Fi password on the router** and use the new one in
   Imager. Same for the `sleepbox` login password if it's reused.
3. In Imager use an SSH public key, disable password authentication, and set a
   fresh unique password for the local user.
4. After first boot, disable cloud-init and delete the three provisioning files
   from the boot partition.
5. Never commit `user-data`, `network-config`, a rendered config with Wi-Fi
   settings, or card images (CLAUDE.md rule 9). Consider adding `user-data`,
   `network-config` and `meta-data` to `.gitignore`.
6. To audit an ext4 root next time without writing: a read-only ext4 reader on
   the PC, or a Linux machine with `blockdev --setro` on the device and
   `mount -o ro,noload`.

## 9. Bring-up results (2026-10-03/04, fresh Trixie Lite 64-bit)

The card was re-flashed as recommended and configured over SSH.

**Worked:**
- Wi-Fi survives `cloud-init.disabled` and deleting `user-data`,
  `network-config` and `meta-data`. NetworkManager keeps the profile in
  `/etc/netplan/90-NM-*.yaml`. Disable cloud-init and reboot *before* deleting
  the files, and confirm `cloud-init status` says `disabled`.
- `/etc/NetworkManager/conf.d/sleepbox-wifi.conf` with `wifi.powersave=2` and
  `connection.autoconnect-retries=0`: `iw dev wlan0 get power_save` reports off.
  Restarting NetworkManager drops the SSH session for a few seconds.
- The §6 `config.txt`, applied as a full-file replacement: boots and rejoins
  Wi-Fi; `temp_soft_limit=70` is honoured on the 3A+; the only ALSA card is
  `snd_rpi_hifiberry_dac`; no Bluetooth devices; DRM shows only `DSI-1`
  (`connected`) and no HDMI connector.

**Needed beyond §6:**
- `dtparam=i2c_arm=on` enables the controller, but `/dev/i2c-1` only appears
  with the `i2c-dev` module: `/etc/modules-load.d/i2c-dev.conf` containing
  `i2c-dev` (raspi-config normally does this). `deploy/install.sh` must do it.
- Pi OS ships `/usr/lib/systemd/journald.conf.d/40-rpi-volatile-storage.conf`
  (`Storage=volatile`), so the volatile-journal item in §7 is already the
  default. For debugging, `/etc/systemd/journald.conf.d/99-sleepbox-debug.conf`
  with `Storage=persistent` overrides it (create the directory first); delete it
  once bring-up is stable.

**Did not work (unresolved):**
- The §6 `cmdline.txt` line made the Pi drop off the network on three separate
  boots, including after a power cycle; restoring the Imager line fixed it each
  time. Cause unknown (no logs were captured; persistent journal was not yet
  enabled). Suspects: removing `console=tty1`, removing `ds=nocloud;…`.
  The Imager line stays for now. `ds=nocloud` is inert with cloud-init
  disabled. Retest one token at a time with the persistent journal on.

**Open issues:**
- **Under-voltage:** `vcgencmd get_throttled` = `0x50000` and repeated
  "Undervoltage detected" in `dmesg` while idle. Replace the supply with a
  5 V 3 A micro-USB unit with an attached cable before M1 measurements; the
  panel and amp will add load.
- Windows does not resolve `sleepbox.local` reliably; reserve the Pi's address
  in the router's DHCP settings and SSH by IP.
